# Auth MVP — Email + Password Accounts

**Date:** 2026-06-04 **Status:** Complete

---

## Goal

Let users create accounts with email + password so they can own and manage their
countdowns (edit, delete, lock). Anonymous countdown creation still works —
accounts are optional and additive.

---

## Scope

### What was built

- Email + password registration at `/sign-up`
- Sign-in / sign-out at `/session` (Rails 8 singleton resource)
- Password reset via email (`/passwords`)
- Session model — token-based, stored in signed httpOnly cookie
- `Current.user` available in all controllers and views
- **Countdown ownership** — logged-in user's countdowns associated via `user_id`
  FK
- **Countdown edit/delete** for owners (`GET /c/:token/edit`, `PATCH /c/:token`,
  `DELETE /c/:token`)
- **Lock/unlock toggle** (`PATCH /c/:token/lock`) — locked countdown cannot be
  edited
- **OmniAuth prep** — `omniauth` + `omniauth-rails_csrf_protection` gems added,
  `Identity` model + migration ready, initializer stub at
  `config/initializers/omniauth.rb`
- Flash messages in layout (notice/alert)
- Nav: Sign in / Sign up links when logged out; email + Sign out when logged in

### What was NOT built (out of scope)

- OAuth providers (Google, GitHub, etc.) — Identity model is ready, no providers
  configured
- "My countdowns" dashboard (`/dashboard`) — Phase 3
- Email sending in development (ActionMailer delivery method = `:test` by
  default)
- Account deletion or email change

---

## Technical Approach

**Generator used:** `rails g authentication` (Rails 8.1 native) — generates
`User`, `Session`, `Current`, `Authentication` concern, `SessionsController`,
`PasswordsController`.

**Sign-up:** `RegistrationsController` hand-written (generator doesn't include
it). `params.expect` for strong params.

**Auth default changed:** `ApplicationController` calls
`allow_unauthenticated_access` globally so all pages remain public. Auth is
opt-in per controller.

**Session mechanism:** Signed httpOnly cookie `session_id` → `sessions.id`
lookup. No JWT, no Redis. Server-side revocation by deleting `Session` record.

**OmniAuth prep:**

- `Identity` model: `provider:string, uid:string, user:references`, unique index
  on `[provider, uid]`
- `config/initializers/omniauth.rb` documents how to wire up a provider
- No routes or callback controller yet

**Countdown ownership:**

- `Countdown.belongs_to :user, optional: true` — anonymous creation still works
- `countdowns.user_id` FK now enforced at DB level
- `owned_by?(user)` / `editable_by?(user)` helpers on model
- `create` assigns `Current.user` if logged in
- Edit/update/destroy/toggle_lock gated by `require_ownership!` before_action
- `locked` boolean (default false) — `require_unlocked!` blocks edit/update when
  true

**Lock semantics:** toggleable by owner. Locked = no edits, no
title/date/password changes. Unlocking re-enables edits. Locking is not
permanent (owner can unlock).

## Routes added

| Method   | Path             | Action                        |
| -------- | ---------------- | ----------------------------- |
| `GET`    | `/sign-up`       | `registrations#new`           |
| `POST`   | `/sign-up`       | `registrations#create`        |
| `GET`    | `/session/new`   | `sessions#new` (sign in)      |
| `POST`   | `/session`       | `sessions#create`             |
| `DELETE` | `/session`       | `sessions#destroy` (sign out) |
| `GET`    | `/c/:token/edit` | `countdowns#edit`             |
| `PATCH`  | `/c/:token`      | `countdowns#update`           |
| `DELETE` | `/c/:token`      | `countdowns#destroy`          |
| `PATCH`  | `/c/:token/lock` | `countdowns#toggle_lock`      |

## Acceptance Criteria

- [x] `GET /sign-up` → 200, registration form
- [x] `POST /sign-up` valid → session created, redirects to root with notice
- [x] `POST /sign-up` invalid → 422, errors shown
- [x] `GET /session/new` → 200, sign-in form with "Create account" link
- [x] `POST /session` correct → session cookie set, redirects
- [x] `POST /session` wrong → redirects back with alert
- [x] `DELETE /session` → cookie cleared, redirects to sign-in
- [x] Nav shows Sign in / Sign up when logged out
- [x] Nav shows email + Sign out when logged in
- [x] Logged-in user creates countdown → `user_id` set
- [x] Owner sees Edit / Lock / Delete controls on `/c/:token`
- [x] Non-owner / anon sees no owner controls
- [x] `GET /c/:token/edit` by owner → 200, edit form
- [x] `PATCH /c/:token` by owner, valid → updated, redirects
- [x] `PATCH /c/:token` by non-owner → 302 with alert
- [x] `DELETE /c/:token` by owner → countdown deleted, redirect to new
- [x] `PATCH /c/:token/lock` (unlocked) → locked, "Locked" badge shown
- [x] `GET /c/:token/edit` when locked → 302 with alert
- [x] `PATCH /c/:token/lock` (locked) → unlocked, edit re-enabled
- [x] `Identity` model + migration present, unique index on `[provider, uid]`
- [x] `config/initializers/omniauth.rb` stub documents provider wiring
