# Custom Countdown Architecture

## Overview

Custom countdowns are user-created, shareable countdown timers. No login
required. Each countdown gets a random token that serves as both its identifier
and its access key.

---

## URL Structure

| Pattern                     | Controller#Action             | Purpose                           |
| --------------------------- | ----------------------------- | --------------------------------- |
| `GET /countdowns/new`       | `countdowns#new`              | Creation form                     |
| `POST /countdowns`          | `countdowns#create`           | Persist + redirect                |
| `GET /c/:token`             | `countdowns#show`             | Shareable live countdown          |
| `GET /c/:token/edit`        | `countdowns#edit`             | Edit form (owner only)            |
| `PATCH /c/:token`           | `countdowns#update`           | Save edits (owner only)           |
| `DELETE /c/:token`          | `countdowns#destroy`          | Delete (owner only)               |
| `GET /c/:token/unlock`      | `countdowns#unlock`           | Password gate (private only)      |
| `POST /c/:token/unlock`     | `countdowns#authenticate`     | Verify password + set session     |
| `PATCH /c/:token/lock`      | `countdowns#toggle_lock`      | Toggle locked state (owner only)  |
| `POST /c/:token/favorite`   | `countdown_favorites#create`  | Favorite (logged-in, public only) |
| `DELETE /c/:token/favorite` | `countdown_favorites#destroy` | Unfavorite                        |

`/c/:token` is intentionally short and distinct from `/countdown/:slug` (which
routes to `holidays#show`).

---

## Token Design

- Generated by `SecureRandom.urlsafe_base64(8)` → 11 URL-safe characters
- Stored in `countdowns.token` with a unique index
- Generated in `before_validation :generate_token, on: :create` — fires before
  validation so uniqueness check on `token` passes on first save
- Retry loop on collision (extremely unlikely at this scale, but safe)

---

## Privacy Model

Two modes:

### Public (default)

- `is_public = true`, `password_digest = nil`
- Anyone with the URL can view
- Token in URL provides minimal obscurity (not security)

### Password Protected

- `is_public = false`, `password_digest` stores bcrypt hash
- `show` gate:
  `is_public? || password_authenticated? || owned_by?(Current.user)`
  - Owners always see their own private countdown — no password prompt
  - Non-owner visitors hit the unlock flow
- `unlock GET` renders a password form
- `authenticate POST` calls `countdown.authenticate(password)` (from
  `has_secure_password`)
- On success: sets `session["countdown_auth_#{token}"] = true`, redirects to
  `show`
- Session is cookie-based (Rails default) — survives browser tab close

**Password validation rule:**
`validates :password, presence: true, if: -> { !is_public? && password_digest.blank? }`
— password is only required the first time a private countdown is saved (no
existing digest). Subsequent edits that don't touch the password field leave
`password_digest` unchanged.

### Why session-based, not JWT or signed URL?

Simple. No external deps. Acceptable for anonymous (no-account) access control.
Phase 3 (full auth) can tighten this if needed.

### CSRF

All `POST /c/:token/unlock` requests require a valid CSRF token. Rails enforces
this by default. The unlock form renders `csrf_meta_tags`-compatible tokens via
`form_with`, so standard browser form submission always works. API/curl access
requires fetching the CSRF token from the form's `<meta name="csrf-token">` tag
first.

## Data Model

```ruby
countdowns
  id              :bigint
  title           :string,   null: false
  token           :string,   null: false, unique index
  target_date     :datetime, null: false
  description     :text
  is_public       :boolean,  null: false, default: true
  locked          :boolean,  null: false, default: false
  password_digest :string    # null when public
  user_id         :integer   # FK → users (nullable; anonymous creation allowed)
  created_at
  updated_at

countdown_favorites
  id              :bigint
  user_id         :bigint,   null: false, FK → users
  countdown_id    :bigint,   null: false, FK → countdowns
  created_at
  updated_at
  # unique index on [user_id, countdown_id]
```

Key model helpers:

- `owned_by?(user)` — true if `user_id == user.id`
- `editable_by?(user)` — owned AND not locked
- `favorited_by?(user)` — `countdown_favorites.exists?(user_id: user.id)`
- `favorites_count` — `countdown_favorites.size`

## Live Countdown Display

Reuses the existing infrastructure:

1. Server renders `target_date.to_i * 1000` as
   `data-countdown-target-timestamp-value`
2. Existing `countdown_controller.js` (Stimulus) reads the value and ticks with
   `setInterval(1000)`
3. Zero server load after initial page render
4. Same pattern used by holiday countdown pages

---

## Stimulus Controllers

### `countdown_form_controller.js`

- Scope: creation form only
- Toggles visibility of password fields based on public/private checkbox
- No server interaction

### `clipboard_controller.js`

- Scope: share page copy button
- Calls `navigator.clipboard.writeText(url)`
- Shows "Copied!" feedback for 2 seconds, then resets
- Graceful: button still visible if Clipboard API unavailable

### `dashboard_tab_controller.js`

- Scope: dashboard page tab switching
- Targets: `tab` (anchor links), `panel` (content divs)
- Reads URL hash on connect to restore active tab
- Writes hash via `history.replaceState` on click — bookmarkable tabs

## Share Experience

After creating a countdown, user lands on `/c/:token` which shows:

1. Countdown title + private/locked badges
2. Live ticking timer (years / months / days / hours / minutes / seconds)
3. Target date
4. Optional description
5. "Copy link" button (clipboard)
6. Favorite/Unfavorite button (logged-in users, public countdowns only) +
   favorite count
7. Owner management panel (Edit / Lock / Delete buttons) if
   `owned_by?(Current.user)`
8. "Create your own →" link

This page is designed to be embedded in a social media share. The `og:title` and
`og:description` meta tags reflect the countdown's title and target date so link
previews work on Twitter/Discord/etc.

## Strong Parameters (Rails 8.1)

Uses `params.expect` (Rails 8.1 API) in `countdown_params`:

```ruby
params.expect(countdown: [:title, :target_date, :description, :is_public,
                           :password, :password_confirmation])
```

This is stricter than `require/permit` — rejects unexpected keys at the
controller boundary.
